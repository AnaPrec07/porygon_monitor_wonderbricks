# Dashboard

`src/download_monitor/dashboards/download_monitor.lvdash.json` is the AI/BI dashboard (the "dashboard.json").
It is generated by `src/download_monitor/dashboards/build_dashboard.py` and deployed by
`resources/download_monitor/dashboard.yml`. It reads only `fct_data_downloads`, `suspicious_downloads` and
`daily_download_summary` (unqualified names; the bundle sets the dataset catalog and schema).

Pages: Overview, Triage, Sensitive data, Large downloads, IP addresses, User drill-down, Data quality.
Filters: date, channel and user on every page except Data quality.

## Before you deploy it (important)

`dm_warehouse_id` defaults to a placeholder, and the dashboard and alerts need a real SQL warehouse id.
`.github/workflows/deploy.yml` deploys `main` to prod, so **set the variable before merging**:

```bash
databricks bundle deploy -t dev --var dm_warehouse_id=<warehouse id>
```

and for prod set `dm_warehouse_id` (and `dm_alert_emails`) in the `prod` target of `databricks.yml` or in the
deploy workflow. Until then a prod deploy fails on the dashboard and alerts resources.

## Changing it

Edit the definitions in `build_dashboard.py`, run `uv run python src/download_monitor/dashboards/build_dashboard.py`
and commit the JSON; a test fails when the JSON is stale, and other tests run every dataset query on local Spark
against fixtures and check that every widget field exists. The layout has not been looked at in the UI from this
repository: open it once and adjust sizes, then either keep editing the generator or export from the UI with
`databricks bundle generate dashboard --existing-id <id>` and drop the generator.
